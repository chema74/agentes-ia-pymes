# Roadmap

## Propósito

Definir la secuencia documental y futura evolución del Agente de Formación Interna para PYMES sin presentar la solución como terminada.

## Estado actual

- Fase documental V1 (*Version 1 – Versión 1*): preparada.
- Implementación mínima V1: futura.
- V2 (*Version 2 – Versión 2*): futura.
- Automatización real: no implementada todavía.

## Fase 0 — Base documental

Objetivo:

- Fijar el lenguaje común del agente.
- Describir el problema formativo.
- Definir el alcance y el fuera de alcance.
- Preparar la estructura de documentación y datos ficticios.

Estado:

- Completada como base documental.

## Fase 1 — Definición de V1 implementable

Objetivo:

- Determinar rutas, módulos, perfiles, evidencias y acciones.
- Establecer reglas mínimas de validación.
- Definir el modelo de datos conceptual.

Estado:

- Preparada en esta documentación.

## Fase 2 — Implementación mínima V1

Objetivo:

- Convertir la documentación en una base funcional mínima.
- Registrar rutas formativas de forma consistente.
- Mantener revisión humana y trazabilidad.

Estado:

- Futura.

## Fase 3 — Validación interna

Objetivo:

- Revisar si la V1 mínima respeta el caso de uso.
- Comprobar que los estados, perfiles y responsables son coherentes.
- Verificar que no se introduce falsa automatización.

Estado:

- Futura.

## Fase 4 — V2 futura

Objetivo:

- Añadir mayor capacidad operativa.
- Mejorar la priorización.
- Incorporar visualización de estados y seguimiento.
- Preparar métricas y KPI (*Key Performance Indicator – Indicador Clave de Rendimiento*) si existiera necesidad real.

Estado:

- Futura.

## Fase 5 — Integraciones avanzadas opcionales

Objetivo:

- Explorar API (*Application Programming Interface – Interfaz de Programación de Aplicaciones*), CRM y Google Workspace solo cuando el diseño base esté validado.
- Valorar LMS si aporta valor y existe base técnica.

Estado:

- Opcional y futura.

## Fuera de alcance inicial

- LMS funcional.
- Código funcional terminado.
- Automatización formativa real.
- Dashboard funcional.
- IA (*Artificial Intelligence – Inteligencia Artificial*) funcional.
- Conectividad con sistemas reales.
- Integraciones productivas.
- Promesas de mejora garantizada o métricas de aprendizaje no verificadas.

## Criterios para cerrar una fase

- La documentación debe estar completa y coherente.
- Los estados deben estar definidos.
- El caso de uso debe estar alineado con el modelo de datos.
- Los ejemplos ficticios deben ser consistentes.
- No debe quedar ambigüedad sobre el nivel real de implementación.

## Criterios para activar la siguiente fase

- Existe una decisión explícita de avanzar.
- Se dispone de una base documental estable.
- El alcance de la siguiente fase está acotado.
- No se mezcla documentación con promesas de software ya terminado.

## Evidencias recomendadas para portfolio

- README del agente con estado real visible.
- Arquitectura conceptual.
- Caso de uso ficticio.
- Modelo de datos mínimo.
- Plan formativo ficticio.
- Flujo manual de validación.
- JSON de ejemplo consistente.

## Próximos pasos inmediatos

- Mantener esta fase como referencia documental V1 preparada.
- Revisar más adelante si se implementa código mínimo V1.
- Alternativamente, continuar con el agente 09 si el foco del portfolio cambia.
