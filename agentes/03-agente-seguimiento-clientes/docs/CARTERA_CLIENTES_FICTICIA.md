# Cartera Ficticia de Clientes del Agente de Seguimiento de Clientes para PYMES

## Propósito del documento

Este documento muestra una cartera ficticia de clientes para validar el modelo de datos, los estados de seguimiento y el flujo previsto del Agente de Seguimiento de Clientes para PYMES (*Small and Medium-sized Enterprises – Pequeñas y Medianas Empresas*).

El documento pertenece a la fase de diseño y validación documental de la V1 (*Version 1 – Versión 1*). No contiene datos reales y no representa una funcionalidad automática implementada.

## Estado actual

- Estado documental: ejemplo ficticio para validación de V1.
- Código funcional: no implementado todavía.
- Automatización de seguimiento: no implementada todavía.
- Recordatorios automáticos: no implementados todavía.
- CRM (*Customer Relationship Management – Gestión de Relaciones con Clientes*): no implementado todavía.
- Dashboard: no implementado todavía.
- Integraciones activas: no implementadas todavía.
- IA (*Artificial Intelligence – Inteligencia Artificial*) funcional: no implementada todavía.

## Advertencia sobre datos ficticios

- Todos los datos son inventados.
- No corresponden a ninguna empresa real.
- No deben usarse datos sensibles en esta fase.
- El documento sirve solo como ejemplo de validación documental y operativa.

Esta cartera no incluye datos bancarios, fiscales sensibles, médicos, legales complejos, credenciales ni contratos reales.

## Contexto ficticio de la empresa

La empresa ficticia utilizada para este ejemplo se llama NexoForm Servicios. Es una pequeña empresa de formación corporativa que diseña talleres internos para equipos comerciales, atención al cliente y mandos intermedios.

Su problema principal de seguimiento es mantener visibilidad sobre clientes activos en distintas fases: propuestas enviadas, formaciones pendientes de cerrar, sesiones ya realizadas, bloqueos por falta de información y clientes que requieren revisión por riesgo operativo.

El equipo implicado está formado por una responsable de operaciones, dos consultores de formación y una persona de soporte administrativo. La responsable interna ficticia principal es Laura Medina, encargada de revisar prioridades, validar próximas acciones y decidir qué clientes requieren atención inmediata.

## Criterios de seguimiento

Cada cliente se revisa con criterios mínimos:

- Estado del cliente.
- Última interacción.
- Próxima acción.
- Responsable interno.
- Prioridad.
- Riesgo operativo.
- Bloqueo.
- Fecha prevista de seguimiento.
- Observaciones internas.

Estos criterios son manuales o basados en reglas simples, no generados por IA funcional. Todavía no existe CRM, dashboard, recordatorios automáticos, Google Workspace, API (*Application Programming Interface – Interfaz de Programación de Aplicaciones*) ni IA funcional implementada.

## Resultado esperado de la cartera ficticia

Esta cartera ficticia permite comprobar:

- Si el modelo de datos es suficiente.
- Si los estados de cliente son útiles.
- Si se detectan clientes sin próxima acción.
- Si se identifican bloqueos.
- Si se pueden priorizar revisiones.
- Si existe revisión humana.
- Si la V1 puede demostrarse sin CRM, dashboard, recordatorios automáticos ni IA funcional.
- Si el caso se entiende como ejemplo de portfolio.

La cartera también permite validar si los campos mínimos son comprensibles para una persona que revise el caso sin acceder a sistemas externos.

## Limitaciones del ejemplo

- No hay captura automática de interacciones.
- No hay conexión con correo.
- No hay conexión con calendario.
- No hay CRM.
- No hay dashboard.
- No hay recordatorios automáticos.
- No hay clasificación con IA.
- No hay uso de datos reales.
- No hay métricas comerciales verificadas.

Estas limitaciones son intencionadas y forman parte del alcance documental de la V1.

## Evolución posible en V2

En una V2 (*Version 2 – Versión 2*) futura, esta cartera podría evolucionar hacia una estructura más operativa si la V1 queda validada.

Posibles ampliaciones:

- Registro en Google Sheets.
- Captura de interacciones mediante Google Forms.
- Dashboard de seguimiento.
- Alertas por correo.
- Recordatorios básicos.
- Integración futura con calendario.
- Resúmenes asistidos con IA.
- Integración futura con CRM.
- Indicadores operativos de seguimiento.

Estas opciones no están implementadas todavía. No existe integración real con Google Workspace, correo, calendario, CRM, dashboard, API ni IA funcional.

## Criterios de validación de la cartera ficticia

Preguntas de control:

- ¿La cartera permite entender el caso sin contexto adicional?
- ¿Los clientes ficticios cubren varios estados?
- ¿Se detectan clientes sin próxima acción?
- ¿Hay bloqueos y riesgos operativos?
- ¿Hay revisión humana?
- ¿Se evita usar información sensible?
- ¿No se promete automatización de seguimiento inexistente?
