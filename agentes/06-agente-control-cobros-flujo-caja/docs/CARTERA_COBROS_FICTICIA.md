# Cartera de Cobros Ficticia

## Propósito

Mostrar un ejemplo ficticio de cartera de cobros para comprobar si la información mínima de una PYME queda suficientemente ordenada.

## Estado actual

- Fase documental V1 (*Version 1 – Versión 1*): preparada.
- Cartera funcional real: no implementada todavía.
- Automatización real: no implementada todavía.

## Advertencia sobre datos ficticios

Esta cartera no representa una herramienta financiera funcional. Es un caso técnico ficticio, útil solo para documentación, validación manual y portfolio. No contiene asesoramiento financiero, fiscal, contable ni legal.

## Contexto ficticio de empresa

La empresa ficticia es una PYME de servicios llamada NexoSur Servicios Profesionales, S.L. Gestiona cobros pendientes de clientes de servicios recurrentes, proyectos cerrados y ajustes de seguimiento con un equipo pequeño.

## Criterios de seguimiento de cobros

- Cada cobro debe tener identificador, estado, prioridad y responsable.
- Cada cobro debe vincularse a una referencia ficticia.
- Si existe riesgo, debe ser visible y tener nivel explícito.
- Las acciones de seguimiento deben indicar el próximo paso.
- Las previsiones operativas deben mantenerse como estimación documental.

## Resultado esperado

La cartera debe permitir detectar qué cobros avanzan, cuáles están vencidos, cuáles presentan bloqueo y qué revisión humana falta para mantener control operativo sin automatización real.

- No existe automatización real.
- No existe conexión bancaria.
- No existe facturación real integrada.
- No existe ERP.
- No existe CRM.
- No existe API.
- No existe IA funcional.

## Evolución posible V2

- Añadir filtros y vistas por cliente.

## Criterios de validación

- Deben existir cobros en distintos estados.
- Deben existir riesgos visibles y coherentes.
- Las acciones siguientes deben estar ligadas a cobros concretos.
- Las previsiones operativas deben ser consistentes con vencimientos y bloqueos.
- La cartera debe coincidir con el modelo de datos y el caso de uso.
