# Inventario Documental Ficticio del Agente Documental Inteligente para PYMES

## Propósito del documento
Este documento muestra un inventario documental ficticio para validar el modelo de datos, los estados documentales y el flujo previsto del agente documental. Pertenece a la fase de diseño y validación documental de la V1 (*Version 1 – Versión 1*).

No contiene documentos reales y no representa una funcionalidad automática implementada. Sirve como ejemplo demostrable para portfolio técnico.

## Estado actual
- Estado documental: ejemplo ficticio para validación de V1.
- Código funcional: no implementado todavía.
- Automatización documental: no implementada todavía.
- Buscador documental: no implementado todavía.
- OCR (*Optical Character Recognition – Reconocimiento Óptico de Caracteres*): no implementado todavía.
- RAG (*Retrieval-Augmented Generation – Generación Aumentada por Recuperación*): no implementado todavía.
- Integraciones activas: no implementadas todavía.
- Dashboard: no implementado todavía.
- IA (*Artificial Intelligence – Inteligencia Artificial*) funcional: no implementada todavía.

## Advertencia sobre datos ficticios
- Todos los datos son inventados.
- No corresponden a ninguna empresa real.
- No deben usarse documentos sensibles en esta fase.
- El documento sirve solo como ejemplo de validación documental.

## Contexto ficticio de la empresa
- Nombre ficticio de la empresa: Nexo Aula Servicios, S. L.
- Tipo de actividad: empresa ficticia de formación corporativa y soporte operativo para pequeñas empresas.
- Problema documental principal: la empresa conserva propuestas, manuales, plantillas y materiales de formación en carpetas con nombres poco consistentes y versiones antiguas mezcladas con versiones vigentes.
- Áreas documentales implicadas: comercial, formación, operaciones, administración y soporte interno.
- Responsable interno ficticio: Clara Montes.

Nexo Aula Servicios, S. L. se usa solo como caso inventado para validar un inventario documental aplicable a PYMES (*Small and Medium-sized Enterprises – Pequeñas y Medianas Empresas*).

## Criterios de inventario
Cada documento se revisa con criterios mínimos:
- Identificación.
- Tipo documental.
- Área o proceso.
- Estado documental.
- Versión.
- Responsable.
- Posibles duplicados.
- Pendientes.
- Próxima acción.

Estos criterios son manuales o basados en reglas simples, no generados por IA funcional.

## Resultado esperado del inventario
Este inventario ficticio permite comprobar:
- Si el modelo de datos documental es suficiente.
- Si los estados documentales son útiles.
- Si se detectan pendientes.
- Si se identifican posibles duplicados o versiones ambiguas.
- Si existe revisión humana.
- Si la V1 puede demostrarse sin buscador semántico, OCR, RAG ni IA funcional.
- Si el caso se entiende como ejemplo de portfolio.

## Limitaciones del ejemplo
- No hay lectura automática de documentos.
- No hay extracción de texto.
- No hay buscador semántico.
- No hay OCR.
- No hay RAG.
- No hay conexión con Google Workspace.
- No hay dashboard.
- No hay clasificación con IA.
- No hay uso de datos reales.
- No hay validación legal, fiscal ni contractual.

## Evolución posible en V2
Este inventario podría evolucionar en una V2 (*Version 2 – Versión 2*) futura hacia:
- Registro en Google Sheets.
- Organización de carpetas en Google Drive.
- Generación de índice documental en Google Docs.
- Dashboard documental.
- Extracción de texto mediante OCR.
- Clasificación asistida con IA.
- Búsqueda documental asistida.
- Integración futura con RAG.
- Alertas sobre documentos pendientes, obsoletos o duplicados.

Estas opciones no están implementadas todavía.

## Criterios de validación del inventario ficticio
- ¿El inventario permite entender el caso sin contexto adicional?
- ¿Los documentos ficticios cubren varios estados?
- ¿Se detectan pendientes reales dentro del ejemplo?
- ¿Hay posibles duplicados o versiones ambiguas?
- ¿Hay revisión humana?
- ¿Se evita usar información sensible?
- ¿No se promete automatización documental inexistente?
