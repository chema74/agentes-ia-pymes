# Capturas Recomendadas para Portfolio

## Objetivo

Las capturas deben demostrar funcionalidad real del repositorio, no promesas ni proyecciones. Cada imagen debe ayudar a verificar que el proyecto existe, se ejecuta en local y produce salidas concretas con datos ficticios.

## Capturas prioritarias

- README del repositorio en GitHub.
- estructura de carpetas.
- salida de `python scripts/validar_repositorio.py`.
- salida de `python scripts/ejecutar_demo_local.py --crear-zip`.
- consola local abierta en `http://127.0.0.1:8765/`.
- edición guiada de un agente.
- ejecución de un agente desde consola local.
- `panel_local.html`.
- `informe_consolidado.html`.
- paquete `evidencias_demo/`.
- `INDICE_EVIDENCIAS.html`.
- `guion_demo_local.html`.

## Capturas que evitaría por ahora

- pantallas que parezcan una web productiva;
- mensajes que sugieran IA funcional;
- cualquier dato real;
- cualquier promesa comercial;
- detalles internos demasiado largos.

## Orden recomendado para enseñar capturas

Una secuencia narrativa sobria puede ser esta:

1. README del repositorio.
2. estructura de carpetas para situar la arquitectura.
3. validación global en terminal.
4. ejecución de la demo reproducible en terminal.
5. consola local en `http://127.0.0.1:8765/`.
6. edición guiada de un agente.
7. ejecución de un agente desde la consola local.
8. `panel_local.html`.
9. `informe_consolidado.html`.
10. paquete `evidencias_demo/`.
11. `INDICE_EVIDENCIAS.html`.
12. `guion_demo_local.html`.

## Texto breve para acompañar las capturas

1. Repositorio local con arquitectura modular, validación global y demo reproducible sobre datos ficticios.
2. Consola y salidas locales orientadas a revisión técnica, trazabilidad y evidencias exportables.
3. Proyecto de portfolio centrado en alcance real, documentación de cierre y demostración verificable, sin integraciones productivas.

## Checklist antes de publicar capturas

- comprobar que no hay datos reales;
- comprobar que se ve claramente `local`;
- comprobar que no se insinúa producción;
- comprobar que el repo está limpio;
- comprobar que la validación global está en verde.
