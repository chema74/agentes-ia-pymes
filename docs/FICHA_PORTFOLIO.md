# Ficha de Portfolio — agentes-ia-pymes

## Resumen ejecutivo

`agentes-ia-pymes` es un portfolio técnico con 10 agentes locales para PYMES. El repositorio muestra arquitectura modular, validación local, datos ficticios y disciplina de alcance. Su valor está en lo verificable, no en promesas de automatización no implementada.

## Problema que aborda

Muchas PYMES trabajan con procesos dispersos, documentación desordenada, seguimiento manual, propuestas poco sistematizadas y control operativo irregular. El repositorio plantea una base técnica para avanzar de forma gradual, incluida la adopción de IA (*Artificial Intelligence – Inteligencia Artificial*), sin saltar a soluciones complejas ni prometer automatización real.

## Solución construida en V1

La V1 implementa una base local verificable:

- 10 agentes separados por dominio.
- Scripts de consola.
- Datos ficticios en JSON (*JavaScript Object Notation – Notación de Objetos de JavaScript*).
- Pruebas `unittest`.
- Validación global.
- GitHub Actions.
- Sin dependencias externas.

## Qué demuestra técnicamente

- Diseño modular.
- Separación por casos de uso.
- Control de alcance.
- Validación reproducible.
- Pruebas automatizadas.
- Tratamiento de errores.
- Documentación profesional.
- Ausencia de dependencias innecesarias.
- Honestidad sobre límites.

## Agentes incluidos

### Agente 01 — Onboarding Inteligente

Valida expedientes ficticios de onboarding y demuestra una revisión local de estructura y campos básicos.

### Agente 02 — Documental Inteligente

Valida inventario documental ficticio y demuestra control técnico de información documental sin OCR (*Optical Character Recognition – Reconocimiento Óptico de Caracteres*) real.

### Agente 03 — Seguimiento de Clientes

Valida una cartera ficticia de clientes y demuestra reglas locales aplicables a un contexto CRM (*Customer Relationship Management – Gestión de Relaciones con Clientes*) simulado.

### Agente 04 — Generador de Propuestas

Valida propuestas ficticias y demuestra comprobación de coherencia mínima antes de una revisión humana.

### Agente 05 — Operaciones para PYMES

Valida tareas y bloqueos operativos ficticios y demuestra ordenación básica de incidencias sin automatización productiva.

### Agente 06 — Control de Cobros y Flujo de Caja

Valida cobros y flujo de caja ficticios y demuestra seguimiento local de estados y previsiones sin prometer resultados financieros.

### Agente 07 — Pipeline Comercial

Valida oportunidades comerciales ficticias y demuestra seguimiento local de pipeline sin integración real con CRM (*Customer Relationship Management – Gestión de Relaciones con Clientes*).

### Agente 08 — Formación Interna

Valida rutas y módulos formativos ficticios y demuestra una base útil para un LMS (*Learning Management System – Sistema de Gestión del Aprendizaje*) simulado.

### Agente 09 — Análisis de Mercado

Valida señales de mercado ficticias y demuestra criterios de revisión sin RAG (*Retrieval-Augmented Generation – Generación Aumentada por Recuperación*) real.

### Agente 10 — Revisión y Cumplimiento

Valida una revisión interna ficticia y evidencias asociadas, con referencia a RGPD (*General Data Protection Regulation – Reglamento General de Protección de Datos*) en un contexto simulado y siempre sujeto a revisión humana.

## Evidencias verificables

El proyecto se puede validar con:

```powershell
python scripts/validar_repositorio.py
```

Este comando valida:

- 10 JSON de ejemplo.
- Tests de los 10 agentes.
- 40 pruebas si cada agente mantiene 4 tests.
- Coherencia técnica mínima del repositorio.

## Límites actuales

- No hay IA funcional.
- No hay API (*Application Programming Interface – Interfaz de Programación de Aplicaciones*) real.
- No hay dashboard.
- No hay Google Workspace.
- No hay integraciones reales.
- No hay RAG (*Retrieval-Augmented Generation – Generación Aumentada por Recuperación*) real.
- No hay OCR (*Optical Character Recognition – Reconocimiento Óptico de Caracteres*) real.
- No trabaja con datos reales.
- No sustituye revisión humana.
- No es asesoría legal, fiscal, laboral, financiera ni regulatoria.

## Valor como portfolio técnico

Este proyecto tiene valor profesional porque muestra capacidad de convertir una idea amplia en un sistema organizado, con criterio de arquitectura, pruebas y validación, documentación y prudencia técnica. También deja una base clara para evolucionar sin mezclar evidencia real con expectativas no implementadas.
