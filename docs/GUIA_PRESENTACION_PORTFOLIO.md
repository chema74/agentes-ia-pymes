# Guía de Presentación para Portfolio

## Objetivo de la presentación

Esta presentación debe explicar que el repositorio demuestra una arquitectura local de agentes para PYMES con datos ficticios, validación global, consola local y evidencias reproducibles. El objetivo no es vender un producto terminado, sino mostrar un trabajo técnico acotado, verificable y documentado de extremo a extremo.

## Mensaje principal

`agentes-ia-pymes` demuestra una arquitectura local y reproducible de 10 agentes para PYMES, con validación técnica, consola local, edición guiada y evidencias exportables, todo ello sobre datos ficticios y sin dependencias externas ni integraciones productivas.

## Qué enseñar primero

Orden recomendado para una revisión técnica o conversación profesional:

1. `README.md`
2. `CATALOGO.md`
3. validación global
4. demo local reproducible
5. consola local
6. informe consolidado
7. paquete de evidencias

## Flujo recomendado de demo

Secuencia recomendada:

```powershell
python scripts/validar_repositorio.py
python scripts/ejecutar_demo_local.py --crear-zip
python scripts/editor_espacio_trabajo.py
```

La revisión interactiva se apoya en la consola local disponible en:

`http://127.0.0.1:8765/`

La lógica de presentación es simple: primero se valida la estructura, después se genera la demo reproducible y, por último, se enseña la navegación local y las salidas producidas.

## Qué demuestra técnicamente

El repositorio permite explicar de forma concreta:

- diseño modular;
- separación por agentes;
- uso de datos ficticios para aislar la demo;
- validación con tests;
- orquestación local;
- reproducibilidad del flujo;
- edición guiada del espacio de trabajo;
- trazabilidad documental y operativa;
- evidencias exportables para revisión.

## Qué no debe venderse como implementado

Debe dejarse explícito que en esta V1 local:

- no hay IA funcional;
- no hay API productiva;
- no hay dashboard productivo;
- no hay Google Workspace;
- no hay datos reales;
- no hay integraciones reales.

## Cómo explicarlo sin humo

La forma correcta de explicarlo es presentarlo como un repositorio técnico de portfolio que empaqueta una arquitectura local, un flujo reproducible de validación y demo, y una colección de salidas verificables. No debe presentarse como un producto en producción ni como una automatización inteligente ya operativa. Su valor está en el criterio de alcance, la claridad modular, la trazabilidad y la capacidad de demostrar trabajo real con límites explícitos.

## Frase breve para LinkedIn o GitHub

Repositorio técnico de portfolio con 10 agentes locales para PYMES, validación global, demo reproducible y evidencias exportables sobre datos ficticios.

Es una base local y reproducible de agentes para PYMES que usé para demostrar arquitectura, validación, edición guiada y generación de evidencias, sin venderlo como una solución productiva ni como IA desplegada.
