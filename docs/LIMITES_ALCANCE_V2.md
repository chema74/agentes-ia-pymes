# ⚖️ LÍMITES Y ALCANCE V2 — AGENTES IA PARA PYMES

## Documento de delimitación técnica y empresarial

---

## 1. Objetivo del documento

Este documento define los límites y el alcance real de la V2 de `agentes-ia-pymes`.

IA (*Artificial Intelligence – Inteligencia Artificial*).

PYMES (*Small and Medium-sized Enterprises – Pequeñas y Medianas Empresas*).

Su función es evitar interpretaciones exageradas del repositorio y aclarar qué demuestra realmente esta versión.

La V2 debe ser ambiciosa, pero honesta.

---

## 2. Qué es este repositorio

`agentes-ia-pymes` es un laboratorio local de agentes de IA aplicados a procesos habituales de pequeñas y medianas empresas.

Su propósito es demostrar, de forma reproducible, cómo podrían estructurarse agentes para tareas como:

- Onboarding.
- Gestión documental.
- Seguimiento de clientes.
- Generación de propuestas.
- Operaciones internas.
- Control de cobros.
- Pipeline comercial.
- Formación interna.
- Análisis de mercado.
- Revisión de cumplimiento.

Pipeline (*Pipeline – Flujo secuencial de procesamiento o trabajo*).

---

## 3. Qué demuestra la V2

La V2 demuestra:

- Organización modular de agentes.
- Uso de datos de ejemplo.
- Validación local.
- Ejecución reproducible.
- Generación de informes.
- Panel local.
- Edición guiada.
- Comparación histórica.
- Exportación de evidencias.
- Documentación de uso.
- Lectura empresarial de casos de uso.

---

## 4. Qué no demuestra la V2

La V2 no demuestra:

- Producto SaaS terminado.
- Sistema multiusuario.
- Seguridad empresarial completa.
- Integración con sistemas reales de clientes.
- Despliegue cloud.
- Uso de datos reales.
- Alta disponibilidad.
- Autenticación empresarial.
- Facturación.
- Monitorización productiva.
- Cumplimiento legal completo.
- Sustitución de consultoría humana.

SaaS (*Software as a Service – Software como Servicio*).

Cloud (*Cloud Computing – Computación en la nube*).

---

## 5. Alcance técnico

El alcance técnico de la V2 es local, demostrativo y reproducible.

Incluye:

- Scripts Python.
- Datos ficticios.
- Tests.
- Documentación.
- Informes.
- Panel HTML local.
- Editor local de demostración.
- Evidencias exportables.

Python (*Python – Lenguaje de programación Python*).

HTML (*HyperText Markup Language – Lenguaje de Marcado de Hipertexto*).

---

## 6. Alcance empresarial

El alcance empresarial es demostrativo.

El repositorio permite entender cómo ciertos procesos de una PYME podrían modelarse mediante agentes de IA.

No pretende ser una solución implantada directamente en una empresa sin adaptación, análisis previo, seguridad, integración y validación profesional.

---

## 7. Datos utilizados

La V2 trabaja con datos de ejemplo y escenarios ficticios.

No debe utilizar datos reales de empresas sin una revisión previa de privacidad, seguridad y cumplimiento.

La filosofía recomendada es trabajar primero con datos sintéticos o anonimizados.

---

## 8. Dependencias externas

La V2 debe mantener enfoque local-first y free-first.

No debe requerir obligatoriamente:

- APIs de pago.
- Tarjetas bancarias.
- Servicios cloud.
- Modelos comerciales.
- Bases de datos externas.
- Plataformas SaaS.

API (*Application Programming Interface – Interfaz de Programación de Aplicaciones*).

Puede documentarse una evolución futura con servicios externos, pero no debe formar parte del requisito obligatorio de ejecución V2.

---

## 9. Uso correcto del repositorio

Uso correcto:

- Portfolio técnico.
- Demostración local.
- Base de aprendizaje.
- Prototipo conceptual.
- Prueba de estructura.
- Material de consultoría.
- Punto de partida para evolución futura.

Uso incorrecto:

- Presentarlo como producto cerrado.
- Prometer implantación inmediata.
- Usarlo con datos reales sin revisión.
- Venderlo como sistema productivo.
- Ocultar sus límites.
- Exagerar capacidades no implementadas.

---

Backend (*Backend – Capa de servidor o lógica interna de una aplicación*).

V1 (*Version 1 – Versión 1*).

V2 (*Version 2 – Versión 2*).

V3 (*Version 3 – Versión 3*).
