## Fase 1 — V1 implementable
La V1 debe ser una primera versión mínima, demostrable y verificable.

Elementos posibles de la fase:
- Flujo básico.
- Datos de entrada mínimos.
- Validaciones sencillas.
- Resultado demostrable.
- Registro básico de salida.
- Revisión humana.
- Documentación actualizada.

[Cada agente deberá adaptar esta fase a su caso real, con foco en contexto de PYMES (*Small and Medium-sized Enterprises – Pequeñas y Medianas Empresas*).]

## Fase 2 — Validación interna
Objetivos de la fase:
- Probar el flujo con datos de ejemplo.
- Revisar errores.
- Confirmar que el alcance se entiende.
- Confirmar que no se prometen funciones no implementadas.
- Ajustar documentación.
- Preparar evidencias sencillas para portfolio.

## Fase 3 — V2 futura
La V2 puede incluir evolución técnica posterior, pero no debe presentarse como implementada.

Posibles ampliaciones:
- Automatización con Google Workspace.
- Dashboard.
- Generación documental.
- Clasificación asistida.
- Integración futura con IA (*Artificial Intelligence – Inteligencia Artificial*).
- API (*Application Programming Interface – Interfaz de Programación de Aplicaciones*).
- Base de datos.
- Alertas.
- Conectores externos.
- Mejoras de experiencia de usuario.

## Fase 4 — Integraciones avanzadas opcionales
Esta fase solo se planteará si la V1 y la V2 tienen sentido técnico.

Posibles integraciones:

- Herramientas internas de empresa.
- Correo electrónico.

- Modelos de lenguaje externos.

[Ninguna integración debe declararse como existente si no está implementada.]

## Fuera de alcance permanente o inicial
Lista guía de límites:
- Agente autónomo completo sin supervisión.
- Producción real sin validación previa.
- Multiempresa real desde el inicio.
- Decisiones sensibles sin revisión humana.
- Sustitución de asesoría profesional.
- Integraciones críticas no probadas.
- Automatizaciones irreversibles.
- Métricas de impacto no verificadas.

## Criterios para cerrar una fase
Preguntas de control:
- ¿La fase tiene entregables claros?
- ¿El resultado puede revisarse?
- ¿La documentación refleja el estado real?
- ¿No se han añadido promesas no implementadas?
- ¿La siguiente fase está justificada?
- ¿El agente sigue resolviendo un problema concreto?

## Criterios para activar la siguiente fase
Condiciones mínimas:
- Documentación base completa.
- Alcance V1 definido.
- Límites claros.
- Flujo mínimo comprensible.
- Riesgos principales identificados.
- Revisión humana contemplada.
- Validación interna realizada cuando proceda.

- Checklist de validación.
- Registro de cambios documentado.
- Referencias de seguimiento con KPI (*Key Performance Indicator – Indicador Clave de Rendimiento*), si existen.
